## Separate execution step

After review, remaining validation and explicit release/deployment authorization:

1. Confirm frontend/backend builds and tests, inspect the full diff, and verify
   that release notes describe current model choices and compatibility.
2. Take and verify a production database and storage backup. Record the prior
   image identities and matching backup path for rollback. Contract-13 backups
   need a contract-13 reader; preserve a pre-upgrade backup for older images.
3. Publish the reviewed commit/tag and versioned images using the existing
   [Docker runbook](DOCKER_DEPLOYMENT.md). `VERSION=1.8.2 ./docker-build.sh`
   **pushes images and updates `latest`**; it is not a local validation command.
4. On the Pi, resolve Compose with explicit `VERSION=1.8.2` and the real registry.
   Inspect resolved image names before pulling/recreating services. Startup must
   apply `20261104173000_ai_pricing_source` (37 migrations total).
5. Record deployed image digests, health, migration state, frontend/backend
   versions and release-note visibility. Then verify normal sign-in, catalogue,
   configuration persistence and agreed translation smoke checks through
   Cloudflare. Label each result **deployed verification**, separately from local
   tests; never infer it from an image build or healthy endpoint alone.

Do not publish a success/deployed milestone until those checks actually run.
